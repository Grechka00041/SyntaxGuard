# Контекстно-свободная грамматика и синтаксический анализ в SyntaxGuard

## Назначение

В проект добавлен отдельный синтаксический модуль `syntax_parser.py`. Он демонстрирует устройство контекстно-свободной грамматики (КС-грамматики) и построение синтаксического дерева с помощью `nltk.CFG` и `nltk.ChartParser`.

CFG-разбор работает параллельно с пунктуационными эвристиками. Его задача — показать возможную структуру предложения, а не определить, правильно ли расставлены запятые. Если учебная грамматика не может разобрать предложение, это не считается пунктуационной ошибкой.

## Как устроена грамматика

Грамматика содержит начальный символ `S`, нетерминалы для структуры предложения и именной/глагольной групп, а также терминалы, соответствующие морфологическим категориям `pymorphy3`.

Примеры продукций:

```text
S -> CLAUSE
S -> CLAUSE CONJ CLAUSE
CLAUSE -> NP VP
NP -> NOUN
NP -> ADJ NP
VP -> VERB NP
VP -> VERB
VP -> VERB INFN
PP -> PREP NP
S -> ADDR CLAUSE
S -> ADDR GREETING
S -> GREETING ADDR
NP -> HOMOG_NP NOUN
GREETING_PHRASE -> GREETING_ADJ NOUN
S -> GREETING ADDR
CLAUSE -> VP ADDR
VP -> VERB INFN
NP -> HOMOG_NP
```

Здесь `S`, `CLAUSE`, `NP`, `VP` и `PP` — нетерминальные символы. Категории `NOUN`, `VERB`, `ADJ`, `PRON`, `PREP` и `CONJ` после морфологической обработки выступают терминалами грамматики. Для обращения предусмотрен отдельный узел `ADDR`. Для приветственных формул используются `GREETING` и `GREETING_PHRASE`; конструкции с глаголом и инфинитивом представлены отдельным терминалом `INFN`. Однородные перечисления типовых существительных и прилагательных объединяются узлом `HOMOG_NP`. Также добавлены правила для наречий, предложных групп и распространённых именных групп с определениями.

## Этапы синтаксического разбора

1. `preprocessor.py` разбивает предложение на токены и присваивает словам морфологические категории.
2. `syntax_parser.py` преобразует морфологические категории в терминальную последовательность. Знаки препинания исключаются из входа CFG, поскольку пунктуацию независимо анализируют модули `rules/`.
3. `ChartParser` сопоставляет последовательность терминалов с продукциями грамматики.
4. Для найденных разборов строятся деревья NLTK. Листья дерева отображают исходные слова, а внутренние узлы — синтаксические категории.
5. `app.py` показывает дерево как для предложений без пунктуационных замечаний, так и для предложений с найденными замечаниями — в раскрывающемся блоке «Синтаксическое дерево (контекстно-свободная грамматика)».

## Пример

Для предложения «Студент читает книгу» морфологическая последовательность может иметь вид:

```text
NOUN VERB NOUN
```

Один из возможных разборов:

```text
(S
  (CLAUSE
    (NP (NOUN Студент))
    (VP (VERB читает) (NP (NOUN книгу)))))
```

Дерево показывает, что именная группа `NP` («Студент») выступает подлежащим, а глагольная группа `VP` («читает книгу») — сказуемым с дополнением.

## Ограничения

- Грамматика намеренно ограничена и охватывает типовые учебные конструкции, а не всю синтаксическую систему русского языка.
- Морфологическая неоднозначность может приводить к нескольким допустимым разборам или отсутствию разбора.
- Вход CFG формируется по частям речи, поэтому дерево отражает структурную гипотезу, а не полный разбор зависимостей и не семантическую интерпретацию.
- Отсутствие дерева не означает, что предложение неправильное.
- Пунктуационные правила продолжают работать независимо и не используют отсутствие CFG-дерева как сигнал ошибки.

## Тестирование

`tests/test_syntax_parser.py` проверяет построение дерева для простого предложения, именной группы с определением, сложносочинённой конструкции, причастного оборота, обращений при повелительном наклонении и короткого причастия, а также обработку знаков препинания и неподдерживаемой последовательности категорий.


## Графическое представление дерева

После построения объекта `nltk.Tree` метод `SyntaxParser._tree_to_data` преобразует
его в структуру `tree_data`, где каждому узлу соответствуют метка и дочерние элементы,
а лексическим листьям — часть речи и исходное слово. Модуль `tree_visualizer.py`
назначает узлам координаты по глубине и порядку листьев и формирует SVG с узлами и
соединительными линиями. Streamlit отображает SVG через
`streamlit.components.v1.html`. Для визуализации не требуется Graphviz или отдельный
графический исполняемый файл. Текстовое дерево NLTK остаётся доступным в интерфейсе.

Подписи пользовательского текста экранируются перед включением в SVG. Для длинных
предложений используется горизонтальная прокрутка.

## Русские пояснения к обозначениям в дереве

В графическом SVG-дереве формальные обозначения КС-грамматики сохранены,
но рядом с ними выводятся русские пояснения. Это позволяет одновременно
показать формальную структуру грамматики и сделать визуализацию понятной
пользователю. Например:

| Обозначение | Русское значение |
|---|---|
| `S` | Предложение целиком |
| `CLAUSE` | Предикативная часть |
| `NP` | Именная группа |
| `VP` | Глагольная группа |
| `PP` | Предложная группа |
| `ADDR` | Обращение |
| `HOMOG_NP` | Однородная именная группа |
| `GREETING_PHRASE` | Формула приветствия |
| `NOUN` | Существительное |
| `PROPN` | Имя собственное |
| `PRON` | Местоимение |
| `VERB` | Глагол |
| `INFN` | Инфинитив |
| `GREETING` | Приветствие |
| `ADJ` | Прилагательное |
| `GREETING_ADJ` | Слово в формуле приветствия |
| `SHORT_ADJ` | Краткое прилагательное |
| `PART` | Причастие |
| `SHORT_PART` | Краткое причастие |
| `DEEPR` | Деепричастие |
| `ADV` | Наречие |
| `PREP` | Предлог |
| `CONJ` | Союз |
| `NUMR` | Числительное |
| `PRED` | Слово категории состояния |
| `PARTICLE` | Частица |
| `INTJ` | Междометие |

В интерфейсе под графическим представлением доступен раскрывающийся справочник
«Расшифровка обозначений в дереве». Текстовая форма `nltk.Tree` остаётся в
формальных обозначениях, поскольку она показывает собственно структуру CFG.

Пример графического дерева с русскими пояснениями сохранён в файле
`docs/examples/syntax_tree_student_ru.png`.


## Расширение грамматики (CFG v2)

В версии CFG v2 добавлены продукционные правила для нескольких распространённых учебных конструкций:

- **Приветствия и обращения:** `S -> ADDR GREETING`, `S -> GREETING ADDR`, `S -> GREETING`; типовые формулы «Дима, привет», «Привет, Дима», «Доброе утро» представлены отдельными узлами. Приветственные слова распознаются по ограниченному набору лексем и характерным позициям; обычное употребление «привет» как дополнения не должно автоматически считаться приветствием.
- **Глагол + инфинитив:** `VP -> VERB INFN` и варианты с дополнением/предложной группой. При этом `preprocessor.py` сохраняет прежнюю категорию `VERB` для пунктуационных модулей, а `syntax_parser.py` извлекает `INFN` из морфологического тега `pymorphy3` только для CFG.
- **Однородные именные группы:** добавлен узел `HOMOG_NP` для некоторых перечислений существительных и прилагательных. Запятые по-прежнему исключаются из входа CFG: их проверяют пунктуационные модули.
- **Обстоятельства и предложные группы:** добавлены правила для начальных наречий, именных групп с определениями и конструкций `PREP + NP`.

Это расширение увеличивает покрытие демонстрационных примеров, но не превращает грамматику в полную грамматику русского языка. Для последовательностей, не покрытых правилами, парсер возвращает `not_parsed`; этот статус нельзя трактовать как грамматическую или пунктуационную ошибку.

### Дополнительные тесты CFG v2

`tests/test_syntax_parser.py` проверяет разбор приветствия с обращением, формулы «доброе утро», последовательность «глагол + инфинитив», однородные существительные/прилагательные, обстоятельство в начале предложения и предложную группу. В `tests/test_morphology_integration.py` добавлены соответствующие проверки на реальных токенах `pymorphy3` (они запускаются в окружении, где установлены зависимости проекта).
